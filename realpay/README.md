# 도깨비방망이

**긱워커의 불규칙한 소득과 세금을 매달 관리하는 AI Agent**
제8회 KB Future Finance A.I. Challenge 2026 출품작 · MVP 프로토타입

기획안(`../kb-ai-challenge-dokkaebi.html`)의 **04. MVP 범위**를 실제로 동작하는 코드로 구현한 개념검증(PoC) 데모.

> 통장 입금 내역(가상)으로 소득 안정성을 진단하고, 다음 달·연간 소득과 세금 대비 참고 금액을 살펴보는 데모.

> [!IMPORTANT]
> 목데이터를 사용하는 시뮬레이션입니다. 실제 계좌를 연결·조회하지 않고, 자금을 이체·보관하지 않으며, 세무 신고·세무 자문을 제공하지 않습니다.

## 무엇을, 왜

긱워커(플랫폼 종사자)는 소득이 불규칙하고 정산이 지연돼 자금 관리가 어렵다. 3.3% 원천징수만으로는 5월 종합소득세를 대비하기 어렵고, 업종코드가 잘못 분류되면 내지 않아도 될 세금을 낸다. 도깨비방망이는 입금 내역을 분석해 이 공백을 메운다.

- **① 소득 안정성 관리 (상위 가치)** — 변동계수·소득 추세·계절성·플랫폼 분산으로 매달 소득 상태를 진단
- **② 세금 예측 & 대비** — 예상 연소득으로 예상 종합소득세·환급을 산출해 미리 준비
- **③ 긱워커 특화 절세** — 플랫폼에 맞는 업종코드 후보를 제시 (신고 코드 결정 아님)

## 구현 범위

- 가상 긱워커 데이터 + 온보딩 설문으로 소득 추정 (콜드스타트 대응)
- 다음 달 소득 점추정치 + 단순 연환산 값 표시
- 단순화된 세법 룰에 따른 추가 납부 대비 참고액 계산
- 플랫폼 연결 업종코드 **검토 후보** 표시
- 모델 입력 요인의 SHAP 기여도 + 선택적 LLM 요약

**구현하지 않은 기능**
- 오픈뱅킹·은행 API 연결, 실제 입금 감지, 계좌 잔액 조회
- 자동이체, 자금 보관, 출금·취소·실패 처리
- 본인인증 및 실사용자 금융데이터 처리
- 신고용 업종코드 결정, 세무 신고 대행, 개인별 세무 자문

## 소득 예측 모델

**다음 달 소득 = LightGBM (pooled panel)**
개인별 모델을 따로 만들지 않고, 450명 × 24개월을 하나의 학습 테이블로 합쳐 "이런 최근 흐름 + 이런 계절 + 이런 유형이면 다음 달은 대략 이렇다"는 패턴을 학습한다. 덕분에 이력이 4개월뿐인 워커도 다른 워커에게서 배운 패턴으로 예측할 수 있다.

**피처 16종**
- 소득 시차: `lag1~3_income`
- 이동평균/변동성: `roll3_mean`, `roll6_mean`, `roll3_std`
- 근무: `workdays`, `workdays_ratio`, `n_platforms_active`
- 계절: `is_holiday_season`, `month_sin`, `month_cos`, `months_since_start`
- 유형(원핫): `pattern_regular / seasonal / irregular`

**검증 2겹**
1. 정량 — worker 단위 5-fold group split(같은 사람 데이터가 train/test에 섞이는 리키지 차단)에서 나이브 베이스라인(최근 3개월 평균) 대비 MAE 개선 확인
2. 설명 — 매 예측마다 SHAP으로 기여 피처를 분해해 근거를 공개(블랙박스 아님)

## 목데이터 생성

23년 플랫폼종사자 실태조사(고용노동부·한국고용정보원) 파라미터를 근거로 합성한다.

- **직군 분포** — 운송·배달, 전문서비스, 컴퓨터 단순작업, 가사·청소·돌봄, 창작, IT, 기타. 직군별 모집단 비율·월 순수입 반영
- **변동 유형** — 규칙형(CV 0.10~0.25) / 계절형(0.20~0.40) / 불규칙·간헐형(0.40~0.80), 유형별 무소득 월 반영 (CV = 월소득 표준편차 ÷ 월평균)
- **기간** — 24개월 (연간 계절 패턴이 두 번 반영되는 길이)
- **콜드스타트** — 설문으로 같은 조건의 기존 워커 코호트 평균과 본인 예상치를 블렌딩. 데이터가 쌓이면 관측 가중치 = `min(1, 유효 활동주 / 12)`로 실측 비중을 높인다 (4주 33% → 8주 67% → 12주+ 100%)

## 중요한 한계와 안전 가정

- **세액 계산은 AI가 아니라 검증된 세법 룰이 한다.** 세율표·경비율은 국세청 홈택스 고시값과 전수 대조했다. 데모는 2,400만원 단일 기준과 기본공제 등 제한된 항목만 반영하며, 인적·특별세액공제와 국민연금 공제(개인 납부액 데이터 없음), 기준경비율의 주요경비 증빙 차감은 미반영한다.
- **단순화 가정은 모두 보수적(세금을 많게 잡는) 방향이다.** 적립 서비스에서 오차는 "많이 떼는 쪽"이 안전하다 — 적게 떼면 5월 폭탄(서비스 실패), 많이 떼면 환급(사용자 보너스). "5월 폭탄 방지"라는 서비스 목적에 정렬한 설계이며, 실서비스 전환 시 세무 전문가 검수가 전제다.
- **연간 소득 예측은 "다음 달 예측치 × 잔여 개월"로 단순화**했다(단순 연환산, 올해 누적 실적 미반영). 실서비스에서는 월별 순차 재귀 예측이 필요하다.
- **추가 납부 대비액은 3.3% 원천징수가 이미 이루어졌다고 가정**하고 부족 예상분만 계산한다. 실제로는 지급명세서·원천징수 여부를 입금별로 확인해야 한다.
- **모든 계좌·금고·적립 표시는 가상 계산값이다.** 실제 자금 이동·보관은 발생하지 않는다.
- **모델은 합성 목데이터로만 평가했다.** 5-fold 교차검증 MAE 약 59.1만원·MAPE 약 38.8%(`model/artifacts/metrics.json`)는 실제 긱워커 데이터에서의 성능을 보증하지 않는다. SHAP은 모델 내부 기여도이지 인과관계·정확성 보증이 아니다.
