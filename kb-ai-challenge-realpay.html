문제

왜 필요한가

①긱워커는 세금을 “몰라서” 손해본다 — 국정감사 실사례

같은 배달 라이더인데 업체마다 업종코드를 다르게 분류합니다.

940909 기타자영업으로 신고 환급금 376,190원
940918 퀵서비스배달원으로 변경 환급금 590,718원
DIFF 코드 하나 차이로 약 20만원 +214,528원

출처: 2021 국회 기재위 국정감사, 김주영 의원 지적

②소득이 불규칙해서 세금을 못 떼어놓는다

3.3% 원천징수만으로는 부족한데, 5월에 종합소득세 고지서를 받고 나서야 안다. “이번 달에 얼마를 떼어놔야 하는지”를 알려주는 서비스가 없다.

③KB는 그릇만 만들고 내용물이 비어 있다

2026.6.30 KB 프리N통장 출시 — 긱워커 전용 파킹통장, 인컴박스로 입금 내역 관리. 하지만 인컴박스는 사용자가 직접 키워드를 등록하는 수동 폴더 기능이다. 판단하는 레이어가 없다.

Positioning 판단하는 레이어가 비어 있다. ← 여기가 우리 자리

AI는 어디에 들어가는가

2곳
경고 대회 이름이 AI Challenge다. “AI 어디 있나요” 질문 하나로 떨어질 수 있음.
①

소득 예측

핵심 축
  • 모델: LightGBM (12일이니 복잡한 시계열 모델 금지)
  • 입력: 과거 월별 소득, 근무일수, 플랫폼 수, 계절/공휴일, 요일 패턴
  • 출력: 다음 달 예상 소득, 연간 누적 예상
  • SHAP으로 기여도 시각화 → “비수기 −18%, 플랫폼 정산주기 변동 −7%”
②

LLM 리포트 생성

보조 축
  • 수치를 자연어 인사이트로 변환
출력 예시 “이번 달은 지난 3개월 평균보다 12% 낮습니다. 연간 예상 소득이 2,400만원 아래로 내려가면 단순경비율 대상이 유지됩니다.”
06

데이터 계획

Mock + 근거

실데이터가 없으므로 목데이터를 생성한다. 대신 근거를 붙인다.

항목내용
규모가상 긱워커 300~500명 × 24개월
분포 파라미터 근거국세청 업종코드별 경비율 고시 (공공데이터포털) + 고용노동부 플랫폼종사자 실태조사
소득 유형규칙형 / 계절형 / 불규칙형
검증 방식시계열 예측 성능(MAE/MAPE)으로 평가 — 클러스터 라벨 복원이 아님

콜드스타트 처리 — 프리N통장이 2026.6.30 출시라 아무도 이력이 없음

  1. 가입 직후 → 온보딩 설문으로 초기 프로파일 생성
  2. 3개월 누적 → 실데이터로 전환
  3. 설문과 실데이터가 충돌하면 실데이터 우선

쟁점결론
